# Renderer 开发规范

在[根规范](../../AGENTS.md)基础上，本文件适用于 `src/renderer/`。先查现有模块与实际调用方，再决定新增位置。

## 模块与复用

- `App.tsx` 负责应用组合与工作区接线，`components/Chat.tsx` 负责会话组合。新增完整面板、菜单、编辑流程或状态机应有自己的模块；入口只保留组合、参数和事件传递。
- 优先检索 `components/`、`lib/` 及 `vendor/hapi/web/src/` 中已有能力。仅复用 `Button` 不代表已经复用了复制、放大阅读、文件保存、恢复草稿等业务行为。
- 常用入口：`MessageActions.tsx`、`ContentDialog.tsx`、`SaveFileButton.tsx`、`ResizeHandle.tsx`、`lib/api.ts`、`lib/recovery.ts`。对话框和基础控件同时检查共享 `components/ui/`；现有封装不适用时，说明缺少的能力再组合底层组件。
- 组件文件采用 PascalCase，hook 以 `use` 开头；其他文件跟随相邻模块的命名，不进行无关重命名。复杂功能可组织成 `components/<feature>/`，仅有少量纯逻辑时直接使用具名 `lib` 文件，不预建整套目录。
- 纯计算与状态转移尽量脱离 React、DOM、网络和存储，让输入输出可直接理解和验证。复杂且独立的规则即使暂时只有一个调用方，也可以单独提取。

## 状态、请求与异步生命周期

- 远端数据沿用 TanStack Query 和共享消息管线，工作区沿用 `lib/workspace.ts`，草稿/送达恢复沿用现有持久化模块。局部开关留在组件内；不为相同数据再建一份 store。
- Hub 请求使用 `lib/api.ts` 的适配客户端，文件与系统能力使用 `window.desktop`。不得在组件内增加绕过主进程认证/校验的直连 Hub 请求。
- query key、缓存、草稿和异步结果须带正确的作用域与会话身份。处理切换会话、切换账户、卸载、断线、重连和请求乱序；旧请求不能覆盖新草稿或错误地关闭新弹窗。
- effect、订阅、计时器、观察器和 worker 必须有清理路径。依赖变化应刷新正确的数据，不靠屏蔽依赖检查、固定延时或重复请求掩盖状态问题。
- 保存/发送等操作必须区分进行中、确认成功、失败和结果不明。只在对应操作确认成功后清除其草稿，保留用户操作期间继续编辑的内容。
- `useMemo`、`useCallback` 和 `memo` 用于有实际成本或引用稳定要求的边界，不机械包裹所有表达式；优化不能改变业务语义。

## 布局与交互

- 沿用主题变量、字号缩放及文章布局约定，参见[文章式对话设计](../../docs/design/chat-article.md)。同组控件复用共同宽度与留白，避免分别添加“修正像素”。
- 修改布局前确认容器归属、flex/grid 的最小尺寸与真正的滚动元素。不要仅用 `overflow: hidden` 掩盖按钮被裁切、正文丢失或错误的滚动区域。
- 以所属会话栏宽度适配双栏，而不只判断整个窗口。浮层需跟随锚点/所属栏，必要时允许自身内容滚动，保证标题、提交、关闭入口可见。
- 新样式按功能限定选择器。优先修改已有规则；不要在 `styles.css` 末尾反复叠加同一选择器、全局标签覆盖或 `!important`。较大的新功能样式可放在同功能文件中显式导入。
- 图标按钮有明确可访问名称；可交互元素支持键盘和可见焦点，展开/选中/禁用的 ARIA 状态与实际一致。复用现有弹层的定位、关闭与焦点恢复能力，不随意重复实现。
- 操作失败时保留输入与重试入口，提示使用既有错误映射；不得弹成功提示却留下失败状态。交互卡片内不展示用户无须判断的 IPC、JSON 或脚本细节。
- 界面检查至少覆盖实际受影响的单栏/双栏、920×640 窗口、最大字号和深浅主题；有长文案时检查代表性的长翻译。验证真实点击命中、完整按钮可见性和键盘焦点，不只看截图。

## 文本、历史与性能

- 用户原文、Agent Markdown、工具输出和文件预览是不同内容路径；改渲染器时逐项确认，不能通过一个全局开关改变全部内容。
- 长文、代码和列表沿用现有虚拟化与 worker 边界。预览可限制渲染量，但完整原文与复制/导出必须保留；流式输出时保留用户正在阅读的位置。
- 调整首屏条数、历史窗口、缓存清理或默认折叠属于用户行为变更。比较修改前后的首次进入、切回会话、向前补载与回到底部行为，记录体验和资源取舍，不将隐藏正文当作无损性能优化。

## 国际化

- 桌面文案使用 `useTranslation()` 和英文原句作为 key；本地翻译在 `i18n/locales/{en,zh,zh-TW,ja,fr,ru,vi}.json`。共享组件沿用其自己的翻译键和目录，不能混淆两套命名。
- 新增或修改文案同步七种语言，包括按钮名称、错误、空状态和辅助说明；动态文本保留参数插值，语言切换后应更新。
- `scripts/add-missing-keys.mjs` 是批量写入工具，`bun run i18n:sync` 会检查并排序文件；两者运行后都要检查 diff，不能顺带覆盖与任务无关的现有译文。

## 验证

TS/TSX 修改执行类型检查，纯规则/状态使用定向单元测试；菜单、滚动、焦点、Portal、测量和布局用生产构建下的 Electron 验证。简单文案或可逆低影响样式调整不强加新测试，复杂交互与已复现回归需要有对应证据。详见[测试规范](../../tests/AGENTS.md)。
