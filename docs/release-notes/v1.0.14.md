# HAPI Desktop 1.0.14

本版接入 OpenCode 运行中追加，并修复快速刷新时的草稿保存，适用于 Windows 10/11 x64。本次提供已校验的本机安装包，公开发布状态以 [GitHub Releases](https://github.com/drch90/hapi-desktop/releases) 为准。

## 升级

1. 从托盘退出正在运行的 HAPI Desktop。
2. 运行 `HAPI-Desktop-1.0.14-win-x64-setup.exe`，使用原安装目录升级；连接设置、标签、草稿和工作区偏好继续保留。

OpenCode 追加需要远端使用配套 HAPI Hub/runner 和 OpenCode 2.x（至少 2.2.5）。运行中的远程会话报告能力就绪后，桌面才显示追加入口。Hub、runner 和 CLI 的部署独立管理。

## 本次更新

- OpenCode 输入框和排队消息支持“优先插入”，普通发送继续排队。旧 runner、未就绪或由终端控制的会话遵循原有能力限制。
- 追加沿用现有消息身份和送达状态。确认期间禁用重复操作，刷新后继续显示等待状态；明确失败和送达不明时保留消息及新草稿，供显式重试或取消。
- 原生接收确认表示 OpenCode 已接收补充内容，当前工具可能执行完才使用这些内容。
- 页面刷新前保存最新草稿，修复刷新早于延迟保存时丢失最后修改的问题，继续按 Hub、账户和会话隔离，并保留会话迁移保护。
- 继续包含 [1.0.13](v1.0.13.md) 的 OpenCode 模型选择与 Codex 问答反馈修复，以及此前的桌面功能。

## 验证记录

业务源码与打包前的功能验证一致，复用类型检查、24 项共享规则测试、70 项桌面状态测试、3 项 Electron 回归及共享源码来源校验，具体命令见[更新记录](unreleased.md)。旧源码已复现 OpenCode 能力判断失败和快速刷新丢失最后修改，修复后通过。

本次通过 `bun run package:win` 重新构建 1.0.14，4 项 Electron 检查通过，覆盖侧栏版本号、会话状态、OpenCode 能力限制、输入框/队列追加、确认延迟、失败重试、快速刷新保留草稿，以及小窗口/双栏中的控制按钮。执行命令：

```sh
xvfb-run -a bun run test:e2e tests/opencode-steering.e2e.ts tests/desktop.e2e.ts --grep 'OpenCode (steering|direct and queued|failed and unconfirmed)|status sections separate individual sessions'
```

已依次执行 `verify-package.mjs record-inputs`、`record-output` 和 `verify`，均通过 `node scripts/limit-cpu.mjs node scripts/verify-package.mjs <命令>` 运行。Windows x64 NSIS 安装包及内层压缩包完整性检查通过，包内版本为 1.0.14；180 个构建文件与测试输出逐一一致，1087 个源码及打包输入未变化，3 个许可/来源文件和 1 个额外资源文件一致。Electron 40.10.6 Windows 运行时缓存与已记录的官方发布元数据及 SHA-256 一致。

构建、测试、打包和校验进程均限制为最多 2 个逻辑 CPU，重型任务串行执行。Electron 使用 Linux / Xvfb 和模拟 Hub，未进行 Windows 实机安装或真实 OpenCode 原生接收验证。
