# HAPI Desktop 1.0.3

本版加入 Claude 活动轮优先插入，修复命令补全闪烁、工具展开、窄栏布局、草稿恢复及计划操作状态，适用于 Windows 10/11 x64。以下为 v1.0.2 之后的变更和验证记录。

## 安装与升级

1. 从托盘退出旧版 HAPI Desktop。
2. 运行 `HAPI-Desktop-1.0.3-win-x64-setup.exe`，使用原安装目录升级；已有连接设置、普通标签和草稿继续保留。
3. 启用 Claude steer 时，按[适配说明](../claude-steer.md)更新远端 Hub 和 HAPI CLI，再重新启动旧 Claude 会话进程。仅更新任意一端不足以启用。

Claude 的支持名单编译在桌面资源中，旧安装包需要重新编译、打包安装。Web 需同步构建部署更新后的共享能力代码。Android 现有接口可复用，但本次未改 APK，也未做 APK 实机验证。

安装包附带 `SHA256SUMS.txt`。Windows PowerShell 可运行以下命令，并与文件中的摘要核对：

```powershell
Get-FileHash .\HAPI-Desktop-1.0.3-win-x64-setup.exe -Algorithm SHA256
```

应用没有自动更新，安装包尚未配置代码签名。

## 修复内容

- **命令和会话补全列表闪烁、滚动回顶部**：本机缓存中的命令与会话匹配结果同步更新，后台状态变化不再清空列表或反复请求命令目录。保持已有行顺序和键盘选择，重命名与删除即时反映；新输入重新排序，菜单滚动不传递到外层对话。
- **工具调用需要展开两次**：普通工具一次点击即可在聊天中展开完整日期、输入和结果。子进程调用记录默认展开，只有一个子调用时直接显示内容，多个子调用可逐项展开查看；具体调用支持完整内容与代码换行。
- **工具详情弹窗过窄且不能调整**：探索分组中的工具详情弹窗默认最大为 1100×780px，可拖动右下角调整，窄窗口自动限制边界。固定标题和关闭按钮，由详情内容统一承担纵向滚动。
- **窄双栏标题被挤没、操作按钮越界**：标题栏按当前会话栏宽度排列，在窄栏内将时间移到下一行，保留标题和全部操作入口。
- **Claude 自定义模型重置**：提供 [远端 runner 配套补丁](../claude-model-persistence.md)，保存 `/model <模型 ID>` 的选择，使其在停止及权限变化后继续生效。该修复需更新远端 HAPI CLI，补丁不包含 steer，也不随桌面安装包部署。
- **Claude 活动轮优先插入**：新增[独立 CLI/Hub 配套补丁](../claude-steer.md)，支持桌面直接插入、队列 Steer 和 Web 队列 Steer。当前工具不中断，以原生 UUID 回显确认接收；重复点击和重连不自动重发，旧 runner 不显示入口。
- **发送内容被后续输入替换（F1）**：点击发送时固定正文、附件选择和定时时间。异步恢复会话或准备附件期间继续输入的内容保留为下一份草稿；原生命令按同一份提交快照识别，重试沿用原发送记录。
- **暂存消息编辑后误删（F2）**：发送成功但条目删除失败后，编辑内容会产生独立发送意图。核对回执时同时比较文字和附件身份；旧发送未确认时继续检查，相同内容重试不会重复发送。
- **恢复会话覆盖目标草稿（F3）**：恢复到已有会话时先保存目标栏的最新输入，再合并双方草稿和附件。双方的未确认发送及排队消息编辑记录分别保留，逐条核对或恢复；重载后仍可继续处理。
- **超过 60 个标签丢失布局（F4）**：移除读取工作区时与打开、移动、合并标签操作不一致的数量限制。已有超过 60 个普通标签的工作区也可正常恢复。
- **重连保留已删除会话计数（F5）**：完整同步移除快照中不存在的旧会话，保留请求期间收到的新建、更新、结束和删除事件。会话名称与待处理计数分别合并，避免局部更新挡住完整数据的恢复。
- **用量统计窗口被限制为手机宽度**：解除通用弹窗的 450px 上限和内容区的固定宽度，弹窗最大宽度为 1100px；内容独立滚动，刷新与关闭按钮位于顶部。已检查 1480×940 和 920×640 窗口下的布局。
- **继续讨论计划后重复显示选择按钮**：将 Codex 当前提案的选择保存在本机的会话状态中。点击“继续讨论计划”后，即使没有输入，切换会话或重载也会保持收起；不同会话相互独立，新提案仍显示选择。操作保留原有草稿，不会发送消息或改变协作模式。

## Claude steer 支持范围

1.0.3 桌面包已包含客户端能力判断，需要配套更新远端 CLI 和 Hub 后启用。普通发送仍排队，显式“优先插入”在当前工具结束后的下一次模型调用前接收；投递撞上原生轮次结束时，等待该输入后续的回显及结果再继续队列。详见 [Claude steer 适配、安装和验证边界](../claude-steer.md)。
