# HAPI Desktop 1.0.21

Codex 等会话的压缩报告对齐 Web：摘要默认折叠，标题和可用的 token 数始终显示；点击标题或使用 Enter／空格可展开、收起完整 Markdown，切回会话或重载后恢复折叠。空摘要不提供展开按钮，后续 token 更新保留当前展开选择。

## 升级

从托盘退出 HAPI Desktop，运行 `HAPI-Desktop-1.0.21-win-x64-setup.exe` 并使用原安装目录升级。连接设置、标签、草稿与工作区偏好继续保留；本次修复使用已有的压缩消息数据，无需新增 Hub 接口。

操作说明见 [上下文与会话设置](../../README.md#通知上下文与会话设置)，主要实现位于 [CompactSummary.tsx](../../src/renderer/components/CompactSummary.tsx)。

## 验证记录

功能修复已通过类型检查、生产构建、5 项压缩报告组件回归及 5 项文章分组测试。3 项 Electron 回归覆盖默认折叠、实时摘要与 token 更新、压缩记录合并与排队确认、切回及重载、历史补载、回到最新消息、鼠标与键盘操作。界面检查包含 920×640、最大字号、单栏／双栏、深浅主题和窄栏滚动到报告末尾。

```sh
bun run typecheck
bun run test --project desktop tests/compact-summary.test.tsx tests/article-transcript.test.ts
bun run build
xvfb-run -a bun run test:e2e tests/compaction-summary.e2e.ts tests/alignment.e2e.ts --grep 'compaction' --max-failures=1
xvfb-run -a bun run test:e2e tests/compaction-summary.e2e.ts --grep 'historical compaction' --max-failures=1
```

上述结果来自版本调整前的同一功能源码；打包时复用未变化的 10 项组件与业务规则结果。1.0.21 类型与版本信息检查通过，并在记录输出摘要的同一构建上通过 4 项 Electron 回归，包含上述压缩交互及状态分区／界面版本号检查。180 个打包输出与该被测构建逐一一致。

构建、测试与打包进程树最多使用 2 个逻辑 CPU，重型任务串行执行；Electron 使用 Linux / Xvfb 和模拟 Hub，未进行 Windows 实机安装验证。打包、Electron 与解包验证日志保存在本机 `build/v1.0.21/`。
