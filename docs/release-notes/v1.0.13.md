# HAPI Desktop 1.0.13

本版修复 OpenCode 会话模型选择和 Codex 问答提交反馈，适用于 Windows 10/11 x64。本次提供已校验的本机安装包，公开发布状态以 [GitHub Releases](https://github.com/drch90/hapi-desktop/releases) 为准。

## 升级

1. 从托盘退出正在运行的 HAPI Desktop。
2. 运行 `HAPI-Desktop-1.0.13-win-x64-setup.exe`，使用原安装目录升级；连接设置、标签、草稿和工作区偏好继续保留。

本次更新桌面客户端；Hub、runner 和 CLI 的部署独立管理。

## 本次更新

- OpenCode 会话的模型目录与可选思考档位分别处理。模型没有档位、档位查询慢或暂不可用时，已发现的模型仍可选择，不再因此反复提示刷新。
- 切换 OpenCode 模型后继续读取对应档位；模型目录本身查询失败时保留刷新重试入口，所有设置以服务端确认值为准。
- Codex 问答提交后显示“提交中…”，接口确认接收后显示“已提交”及等待 Agent 确认的提示。当前卡片保持只读，避免连续点击重复提交，完成状态仍由远端通知决定。
- 问答请求明确失败时保留选项与备注供重试；切换问题后返回的旧结果不再影响新卡片。新增提示支持七种桌面语言，并验证小窗口、双栏及最大字号。
- 继续包含 [1.0.12](v1.0.12.md) 的远端 CLI 安装检测、11 种 CLI 的创建与会话设置，以及此前的发送恢复和界面修复。

## 验证记录

业务源码与打包前已完成的修复验证一致，复用类型检查、719 项单元/共享测试、9 项 Electron 回归、七种语言 377 个文案键和共享源码来源校验。具体命令与覆盖范围见[更新记录](unreleased.md)。

本次通过 `bun run package:win` 重新构建 1.0.13，6 项 Electron 检查通过，覆盖侧栏和设置中的版本号、OpenCode 无思考档位及慢查询时切换模型、模型刷新恢复、Codex 连续点击只提交一次、等待确认、失败重试，以及小窗口/双栏下的状态提示。执行命令：

```sh
xvfb-run -a bun run test:e2e tests/session-models.e2e.ts tests/question-submission.e2e.ts tests/desktop.e2e.ts --grep 'OpenCode models remain selectable|OpenCode refresh recovers|Codex answer feedback stays visible|Codex rejected answers keep|Codex submission status and controls|status sections separate individual sessions'
```

已依次执行 `verify-package.mjs record-inputs`、`record-output` 和 `verify`，均通过 `node scripts/limit-cpu.mjs node scripts/verify-package.mjs <命令>` 运行。Windows x64 NSIS 安装包及内层压缩包完整性检查通过，包内版本为 1.0.13；180 个构建文件与测试输出逐一一致，1087 个源码及打包输入未变化，3 个许可/来源文件和 1 个额外资源文件一致。Electron 40.10.6 Windows 运行时缓存与已记录的官方发布元数据及 SHA-256 一致。

构建、测试、打包及验证进程均限制为最多 2 个逻辑 CPU，重型任务串行执行。Electron 使用 Linux / Xvfb 和模拟 Hub，未进行 Windows 实机安装或真实远端响应耗时测量。
