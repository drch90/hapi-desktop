# HAPI 上游对齐记录

最新检查见下方 [v0.34.6 兼容对齐](#hapi-v0346-兼容对齐)，对应桌面 1.0.23，交付情况见 [版本说明](release-notes/v1.0.23.md)。以下保留历次来源和交付记录。

最初的 v0.33.5 检查以同级 HAPI 仓库的 `289c2bb1` 为来源，该提交包含上游 v0.33.5（`ba2b5c56`）及本地扩展。桌面改动随 [1.0.9 本机安装包](release-notes/v1.0.9.md)提供。

桌面端采用选择性同步：更新共享协议、聊天归一化与对应 fixtures，并接入现有功能需要的接口和展示逻辑。`UPSTREAM.json` 的原始基线仍为 v0.30.7（`0239edf3`），新来源单独记录为 backport；桌面 IPC、内存消息缓存、文章式工具卡和本地文件操作适配继续由可重放补丁记录。

## 已对齐

| 上游变化 | 桌面处理 |
| --- | --- |
| Codex 异步问答 | 新 ID 包含嵌套 JSON 转义。原有路径校验将其当作非法路径，导致答案到达 Hub 前返回 `ACTION_FAILED`。现在只在明确的问答提交/取消路由中，将规范编码的请求 ID 作为不透明标识处理；其他路由仍校验来源、路径与方法。 |
| Codex 原生 Auto 权限 | 共享权限目录更新为 `default`、`read-only`、`autoReview`、`yolo`，新建与运行时设置沿用同一目录。 |
| Codex 模型发现 | 支持并发客户端的会话优先读取当前 app-server 模型目录；只有 RPC 目标缺失才回退机器发现。 |
| Claude 模型与 effort | 从 runner 读取 CLI 模型目录，保留旧版本分组及当前未列出的模型；发现不可用时回退 Opus、Fable、Sonnet、Haiku。切换到不支持原 effort 的模型时，同一次模型请求清除该 effort；新建表单同步限制。 |
| 上下文压缩 | 展示可用的摘要与实际/估算 token 数，按压缩 ID 合并先后到达的记录。队列识别等待压缩完成的消息，等待期间隐藏重试入口，避免把尚未确认的消息重复提交。 |
| 历史加载 | 切回会话的最新页由 200 条改为 20 条；首次打开仍取 20 条，若只有工具活动则尝试补取一页上下文。点击“加载更早的消息”每次补载 200 条；记录包含工具与事件，合并后可能只显示少量正文。1.0.10 沿用该策略。 |
| 命令结果与子代理 | 同步晚到命令结果的身份、失败状态、原生耗时及缓存统计；缺少开始记录时不伪造开始时间。保留窗口内子代理消息需要的父调用，并补齐无法归属父卡的待处理请求。 |
| 临时标题 | 会话列表、标签和通知使用 Hub 从首条输入生成的 `promptTitle`，正式名称与摘要仍优先。 |

## 本次界面修复

- 用户消息按原文显示，保留空格、Tab、连续空行、反斜杠、`#` 注释、列表符号及代码围栏。可识别链接继续支持跳转；复制和放大阅读使用相同原文。Agent 回复及文件预览保持 Markdown。
- 正文、排队消息、问答、暂存列表和输入框共用文章宽度与左右留白。长路径、长附件名可以换行，窄窗口与双栏按所在会话收缩；暂存编辑弹窗也跟随所属栏。正文滚动区在被下方面板压缩时不会覆盖排队或暂存按钮。

## 保留的桌面差异

跨客户端已读同步、按最后用户输入排序、名称锁定、会话分叉/回退、原生历史导入及 Markdown 本地图片是独立功能接入。本次不替换桌面既有的本机未读记录、状态分组及文件预览规则；它们不阻塞上述通信契约。完整功能差异见 [README](../README.md#尚未适配的-web-功能)。

Hub/runner 负责异步答案送达、压缩确认与模型发现；旧 runner 不提供 Claude 模型目录时仍可使用回退选项。桌面修复需要安装由本次源码构建的客户端，单独更新 Hub 不会替换现有桌面包。

## 验证

所有类型检查、构建及测试均通过 `scripts/limit-cpu.mjs` 限制到最多 2 个逻辑 CPU，重型任务串行执行。结果记录在 [版本说明](release-notes/v1.0.9.md#验证记录)。Electron 使用模拟 Hub，覆盖原文与复制、异步答案的实际 IPC 提交、宽屏/双栏/大字号布局、暂存编辑、模型切换、压缩回执与历史补载。

来源清单记录 973 个共享文件，其中 175 个补丁文件均可还原到原基线并重放；本次来源另记录 138 个 v0.33.5 参考文件。功能验证日志和模拟界面截图保存在本机 `build/upstream-alignment/`，安装包与打包记录保存在 `build/v1.0.9/`。

## Antigravity 原生会话（1.0.17）

- 来源为本地 HAPI `8bc5b1d8dfe988e0cd35691da6a511b6b2460223` 之上的未提交工作树，11 个源文件的实际 SHA-256 记录在 `UPSTREAM.json` 独立 backport 中。原始 v0.30.7 基线与此前来源记录保持不变。
- 同步共享权限目录的 `auto` / `plan` 与 Antigravity 追加能力；桌面新建和会话设置已有原生下拉与按账户/机器隔离的偏好，无须导入 Web 新建页的状态或 YOLO 迁移逻辑。Grok 的 Auto 能力限制只作用于 Grok。
- `agy_message.data.id` 作为流标识交给既有归一化/归并管线，累计快照替换同一回复，保留模型元数据。带流标识的原文不执行旧任务日志清理；没有标识的历史消息继续使用旧规则。同步六份原生/通用工具审批与流式 fixture 及生成用例。
- 思考与工具沿用公共消息类型；审批继续用独立回复 ID 提交，`toolCallId` 只用于关联工具。已撤回的旧回复不覆盖新请求，允许、本会话允许、拒绝与失败重试通过现有 IPC。
- 输入框与队列复用 `active`、远端控制和 `steeringActive: true` 判断。普通消息仍排队，待确认与送达不明状态、原消息 ID、新草稿及重载恢复保持现有规则。
- 实际界面检查复现 920×640 双栏、最大字号下较长权限文案把发送按钮挤出窗口的问题；排队区改为允许收缩并滚动，优先保留完整发送／中断入口，回归同时检查实际点击命中。
- 上游的原生终端进程、预热、模式切换、工具参数映射、工具边界接收与单条等待回执由 Hub/runner 提供；远端需要该更新与 agy 1.5.2+。本次交付仅更新桌面项目，未部署同级 HAPI 服务。

新增 [补丁刷新脚本](../scripts/refresh-upstream-patch.mjs) 从原始基线提交生成来源清单与补丁，支持源 checkout 已前进或含未提交改动；先登记实际 backport，再刷新和验证。新增/修改文件均经过基线还原与正向重放。验证和本机安装包记录见 [1.0.17 版本说明](release-notes/v1.0.17.md)。

## HAPI v0.34.6 兼容对齐

来源为同级 HAPI `58565b47c5656519417cb019c4d0d4d88c3e739e`，其中 `b16d36db` 合并上游 v0.34.6。检查结束时源仓库为 `57e8ffd2`；后续的 `26ae3da8`、`57e8ffd2` 涉及 CI、发布流程、文档及 Android 签名构建，已核对本次参考的共享协议、Web 与通知文件仍与 `58565b47` 一致。准确源文件 SHA-256 单独登记在 `UPSTREAM.json` 的 backport，原始 `0239edf3` 基线及此前七份 backport 原样保留。

| 已确认的差异 | 桌面处理 |
| --- | --- |
| 新 Hub 在 `messages-indeterminate` 中使用 `dispatching: true`，消息快照使用 `deliveryPending: true` | 接收两种新标记，同时兼容旧 `messages-dispatching`；待确认期间锁定编辑、取消和重试，已消费消息不被晚到的待确认事件降级。REST 队列读回不覆盖较新的 SSE 状态。 |
| `session-updated` 新增严格的 `attachedJob` 补丁 | 更新协议校验，避免连带丢弃同一事件中的会话字段；列表缓存按版本保存与清除任务，旧心跳不能恢复已清除任务。完整 detail 刷新保留列表独有的任务及定时字段；本次未加入进度条 UI。 |
| ACP 工具调用原地合并后保持原始 ID/游标，单纯补载新消息会漏更新 | 缺口恢复先追赶完整区间，再按 ID 合并最新页；额外刷新最新页之外最多 20 条仍未完成的缓存工具记录。保留历史游标与窗口；刷新失败保留待恢复状态，旧 context 响应不覆盖新的 SSE 记录，epoch 变化沿用权威窗口重置。 |
| 选项问答限制自由输入，非阻塞问答允许取消 | 支持 `allowFreeText: false`、跳过、忽略和已取消历史状态；沿用桌面滚动布局，等待远端确认期间锁定操作，失败保留答案，忽略切换问题后的旧回执。新增桌面文案提供七种语言。 |
| OpenCode 小写工具名、命令名卡片与读取文件包裹 | 使用共享别名与终端判定，正确显示命令、换行输出和文件行号；保留桌面文章式卡片、详情尺寸和完整内容查看。 |
| Copilot/Kimi 提供模型相关思考档位 | 接入当前会话发现接口，缓存按会话/模型隔离，仅允许提交实际选项；发现暂不可用不阻止模型选择，新建参数继续沿用明确的支持列表。 |
| 新的 Antigravity/OpenCode 轮次摘要与空 reasoning 记录 | 同步摘要归一化、后到摘要归属与对账字段；空思考内容不再拆散相邻工具分组。 |
| Agent 内部 task notification 造成额外系统提醒 | 停止将内部任务消息当作会话完成通知；真实会话结束、ready、审批和问答提醒继续保留。 |

首屏/切回仍请求 20 条，历史页仍为 200 条；正常重连以既有窗口上限为边界。消息正文继续按桌面原文/Markdown 路径分别展示，聊天记录不写磁盘缓存；草稿、队列身份、账号隔离、默认折叠和会话排序保持既有契约。Codex 工具卡的 `reasoning` 标签沿用桌面文案，没有同步上游仅措辞性质的 `effort` 改名。锁文件已有 `katex@0.16.47`、`ws@8.22.0`，本次不需要新增或升级依赖。

服务端全文搜索、命中上下文导航、附属任务进度条、Web 简洁显示选项、presence/跨端已读与新排序规则，以及分叉/回退、名称锁定和原生历史导入仍是独立功能接入。保留协议字段不代表桌面已提供相应界面。新模型能力与原生消息送达需要配套 Hub/runner；本次未修改或部署同级服务。桌面改动纳入 1.0.23，安装包与轻量覆盖包的校验见 [版本说明](release-notes/v1.0.23.md)。
